# 03 · AI 使用记录

这份记录回答一个问题：**这件东西里，AI 到底做了什么、人做了什么。**

## 一、结论先说

- **运行时不含任何模型调用**：网页不联网、不加载模型权重、不向任何服务发请求（e2e 断言 request 列表，AC-7）。
- **画面里没有一张 AI 生成的位图**：全部图形由 Canvas 2D 程序化绘制（`scripts/verify.sh` 的 hygiene 段会拒绝任何 png/jpg/webp）。
- **AI 的位置是「写代码与文案的助手」，不是「出图工具」**：代码、测试、文档由 WorkBuddy（CodeBuddy 内核）里的
  AI 助手在人的指令下写成；人负责定方向、选赛、验收、改稿与拍板。

这不是省事，是取舍：这件作品的机制是「照到哪里才亮、离开就褪」——
生成式模型给不了这种因果，它只能给一张静态的好看。我们宁可要一个能动的因果。

## 二、工作流（可核）

| 环节 | 谁做 | 说明 |
| --- | --- | --- |
| 选赛、资格核查、条款判断 | 人（张一）定，AI 查证并留痕 | 赛事公告原文与截止时间抓在 `docs/04-SOURCES.md` |
| 作品立意（散宴之后的屋子、烛与记忆） | 人定方向，AI 出候选并自查是否与《朝元》重复 | 差异表见 `docs/00-SPEC.md` §7 |
| 代码（状态机、绘制、光照、余痕） | AI 写，人验收 | 26 单测 + 19 项 e2e + 15 项界面量测，`npm run verify` |
| 视觉判断（第一眼） | **不看 AI 的自评**，交外部模型盲排 | 三轮记录与评委原话在 `proof/gate-d/README.md` |
| 文案（题记五行、说明、提交表） | AI 起草，人改 | 题记全部 ≤ 18 字，单测卡住 |

## 三、用到的工具

- **WorkBuddy（CodeBuddy 内核）+ multica-cb 技能**：主控与施工同一台机器，同一会话。
- 模型：`BC-DeepSeek-V4.1-Flash-1017`（中档）。主控自己的六维打分**不计入**闸 D，闸 D 只看外部盲排。
- 盲排评委：三个互不通气的子代理（文博策展人 / 视觉设计总监 / 普通观众三种提示），只看图、不知道哪张是我们的。

## 四、被否掉的 AI 用法

| 想法 | 为什么没做 |
| --- | --- |
| 用生图模型出「工笔人物」立绘 | 试过一版：人物读成"披风帐篷"，且和"照到哪里才亮"的机制打架。最终整幅不出现完整人物 |
| 用生图做绢本纹理贴图 | 叠上去像雾，把暗部糊成灰；改成纯色 + 接触阴影 |
| 让模型在线生成题记 | 运行时不联网；且题记要能背下来，不能每次不一样 |

## 五、可复核的痕迹

- `docs/00-SPEC.md`：验收条件 AC-1～AC-15，逐条对应到测试或脚本。
- `proof/ui/report.md`：界面量测（字号 / 对比度 / 溢出 / 文字占比）。
- `proof/gate-d/README.md`：三轮盲排、字母钥匙、评委原话。
- `proof/trace/`：从第一版到定版的取舍记录。
